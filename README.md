# CMaNGOS TBC 竞技场赛季控制器 V5

[English documentation](README.en.md)

Windows 离线工具：通过中文批处理菜单管理准备期、S1–S3、结算预览、正式发奖和受保护的撤销。设计参考 [CMaNGOS Classic 安其拉事件控制项目](https://github.com/zgdjenjciksijkjkc/cmangos-classic-ahnqiraj-event-control)。本工具不需要重新编译核心。

**适用范围：已安装 V4 竞技场场景布局的 CM70 / CMaNGOS TBC 2.4.3 定制服务端。本仓库不是原版 CMaNGOS 的通用安装器，也不包含 V4 数据初始化程序。** 不满足版本或数据库校验时会拒绝执行，请勿删除校验来强行使用。

## 下载与安装

使用 GitHub 的 **Code → Download ZIP**，或者下载仓库中 `downloads/cmangos-tbc-arena-controller-v5.zip`。后者仅包含运行文件和说明；安装任意一种即可，不要重复嵌套解压。

推荐把解压后的整个文件夹放到服务器根目录的**下一层**。服务器根目录指同时存放 `mangosd.exe`、`mangosd.conf`、`aiplayerbot.conf` 和 `Database` 的目录，不是游戏客户端目录。

```text
C:\cm70\70CM20260312\                   ← 服务器根目录
├─ mangosd.exe
├─ mangosd.conf
├─ aiplayerbot.conf
├─ ahbot.conf
├─ Database\bin\
│  ├─ mysql.exe
│  ├─ mysqld.exe
│  ├─ mysqldump.exe
│  └─ mysqladmin.exe
├─ data\                                ← 实际游戏数据以 DataDir 配置为准
└─ cmangos-tbc-arena-season-control\      ← 本工具文件夹，可以改名
   ├─ 启动竞技场控制器.bat
   ├─ Start-Arena.ps1
   ├─ ArenaControl.ps1
   ├─ Storage.psm1
   ├─ Shadow.psm1
   ├─ WorldLayout.psm1
   ├─ RewardEngine.psm1
   ├─ NativeWinnerAdapter.psm1
   ├─ README.md
   └─ README.en.md
```

### 路径与文件夹名称要求

| 项目 | 要求 |
|---|---|
| 工具文件夹名 | 没有固定名称；`cmangos-tbc-arena-season-control`、GitHub 的 `cmangos-tbc-arena-season-control-main` 或日期编号名称均可。原交付的中文文件夹名已测试。 |
| 文件夹位置 | 双击入口只自动检查自身目录和直接上级目录。**不能多套一层目录**，例如 `服务器\工具\解压包\启动竞技场控制器.bat` 无法自动识别根目录。 |
| 运行文件 | 上面列出的 BAT、两个 PS1 和五个 PSM1 必须留在同一目录，保持文件名不变。不要只复制 BAT。 |
| 平铺安装 | 也支持将这些运行文件全部直接放在服务器根目录；更推荐独立文件夹，避免混放或覆盖。 |
| 服务器根路径 | 没有硬编码要求必须叫 `70CM20260312`，但仅测试过本次 CM70 环境。建议短的本地路径，例如 `C:\cm70\70CM20260312`；其他根路径字符组合未完整验证。避免 `[`、`]` 等 PowerShell 通配符字符，及网络共享、过深目录。 |
| 工具包改名 | 可以改变独立工具文件夹名称，因为账本不绑定工具包名称；仍须保持文件完整、位于根目录下一层。 |
| 安装后的服务器移动 | **首次启用后不要改服务器根目录名称、移动到另一个盘或更换所连接数据库。** 控制记录绑定根路径、数据库端口和库名。迁移需要同时处理数据库和原备份，本版无自动迁移功能。 |
| 备份目录 | 自动位于服务器根目录 `.arena-settlement-v5`。不能删除、改名、单独搬走或上传 GitHub。里面可能含账户、角色、配置密码和数据库副本。 |
| 编码 | PS1/PSM1 使用 UTF-8 BOM，入口使用 UTF-8 控制台。不要另存为 ANSI 或无 BOM 后再用 Windows PowerShell 5.1 执行。 |

**正确：** `C:\cm70\70CM20260312\cmangos-tbc-arena-season-control-main\启动竞技场控制器.bat`

**错误：** `C:\cm70\70CM20260312\下载包\cmangos-tbc-arena-season-control-main\启动竞技场控制器.bat`

高级用法可以显式指定根路径，但日常用户无需使用命令行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\tools\arena\ArenaControl.ps1" -ServerRoot "C:\cm70\70CM20260312" -Action Status
```

`-ToolRoot` 是可选的 MySQL 工具根目录参数，程序在其下查找 `Database\bin`；它不是运行脚本所在目录。默认与服务器根目录相同。

## 运行前提

- Windows，已验证 Windows PowerShell 5.1 和实际 BAT 入口；菜单目前为中文。
- 必须先关闭所有 `mangosd` 世界服务进程，正式 MySQL 保持运行。准备期也可以继续玩普通战场。
- 对服务器根目录、工具备份目录和临时目录有写权限；数据库账户能读取、备份并执行本工具的表更新及建表操作。
- 使用服务端自带、已测试的 MySQL 5.7 工具。预览需要数 GB 或更多空闲空间，实际取决于数据库大小；副本端口 `127.0.0.1:13318` 和世界端口 `18086` 必须空闲。
- 原配置中的 `DataDir` 必须有效，依赖的 DLL、核心数据及配置必须齐全；副本会使用这些文件。
- 配置中的五组数据库连接必须是同一本地实例和相同账户/密码；世界库为 `tbcmangos`，角色库为 `tbccharacters`。不支持远程数据库或随意改名。
- 关键角色、竞技场统计、邮件与物品表，以及控制器账本，必须为 InnoDB。
- 要求 `AiPlayerbot.RandomBotAutoJoinBG = 0`；不关闭普通战场机器人配置，也不按真人或机器人过滤领奖名单。
- 事件 33 不能意外活动。V4 事件、条件和 NPC 布局必须通过严格检查。
- 已测试核心 `mangosd.exe` SHA-256：`66CF3C31A26649B4BF6ABC690281508D464D42BC644F37B999EF4EB1D000793E`。其他二进制会被拒绝。

先保留完整服务端数据库备份。工具的操作快照有特定恢复范围，不能代替完整灾难恢复备份。

## 使用方法

1. 退出游戏，关闭 `mangosd`，保持 MySQL 运行。
2. 双击 `启动竞技场控制器.bat`。
3. 选择菜单；需要确认的操作输入 `YES` 或 `Y`，确认匹配不区分大小写，其他输入取消。
4. 等操作完成、返回菜单后选 `0` 退出，再启动服务端进入游戏。预览期间不要启动正式世界服。

| 选项 | 作用 |
|---:|---|
| 1 | 准备期，不结算、不发赛季奖励。已有后续赛季进度或结算时禁止跳回。 |
| 2 | 开始 S1。 |
| 3 | 开始 S2，必须先完成 S1 结算。 |
| 4 | 开始 S3，必须先完成 S2 结算。 |
| 5 | 当前赛季结算预览：在独立数据库和核心副本中计算名单，正式库不发奖。 |
| 6 | 当前赛季正式结算：必须有仍然有效的预览；发奖后关闭赛季内容，进入等待下一季的状态。 |
| 7 | 查看状态。它显示离线设置和账本，不能代替实际开服后的 NPC、邮件验证。 |
| 8 | 撤销最近一次操作。只有操作后的数据仍匹配、记录完整时允许；开服、新游戏进度、领奖等通常使其拒绝。不能连续撤销一个撤销。 |
| 9 | 恢复中断操作。检查数据库事务是否已提交；已提交则保留结果，不重复发奖。 |
| 10 | 恢复 V5 启用前的场景及识别出的旧入口，不回档角色游戏进度。存在正式结算奖励时禁止执行。 |
| 11 | 查看最近预览名单；这是生成时的报告，不能据此判断当前是否已发奖。 |
| 0 | 退出。 |

推荐顺序：`准备期 → S1 → 预览 → 正式结算 → S2 → 预览 → 正式结算 → S3 → 预览 → 正式结算`。正式结算后就是等待状态，不需要单独选“休赛期”。本版无 S4 开始或结算选项。

## 结算规则与奖励

采用“**保留该定制端获奖比例与资格，只修正各赛季奖励**”。原核心在隔离副本中计算获奖名单，真人和机器人都参与；这不是原版历史服百分比的完整复刻。

| 赛季 | 角斗士坐骑物品 ID | 赛季冠军头衔 ID | 其他竞技场头衔 ID |
|---|---:|---:|---|
| S1 | 30609 | 通用角斗士 42，不添加后来怀旧服的地狱角斗士 | 42–45 |
| S2 | 34092 | 62（残酷角斗士） | 42–45 |
| S3 | 37676 | 71（复仇角斗士） | 42–45 |

- 坐骑仅发给预览中对应档次的角色，每个角色每季最多一份，多组别只取最高奖励。
- S2/S3 季冠只补给每个组别唯一第一名队伍中、原端已判为角斗士的成员；并列第一会拒绝自行选人。
- 原核心在副本中产生的错误跨季坐骑、货币改写等副作用不会导入正式库。
- 正式结算保留荣誉和竞技场点数；不执行周积分分发。队伍统计在下一季开始时按副本的原端重置结果处理，不删除队伍。
- 永久头衔保留，临时竞技场头衔在后续结算中更新。未达到本端资格的角色不会因为“开启了赛季”而自动获奖。

## 可逆性、旧版与事件 56

工具使用操作前快照、SQL 事务、数据库防重复账本和中断记录。世界事件等非事务表单独备份/恢复；角色奖励、邮件、物品和账本在同一个事务内提交。失败后会尝试恢复；需要人工处理时保留记录并给出错误。

首次启用会识别服务器根目录及直接子目录中带指定标记的旧 `ArenaSeasonControl.ps1`，改名为 `.disabled-by-v5` 保留。以后仅使用 V5 入口，不能混用旧版。遇到同名新文件不会强行覆盖。

V5 保持事件 56 连续活动，但移走其 S4 内容并隔离 S4 商品条件，以避免本端已复现的原生结束回调。**因此准备期或 S1–S3 的 `game_event_status` 中仍有事件 56，是本版保护设置，不能按旧版“只允许一个事件”来判断。** 当前赛季要同时看 V5 账本和内容关联。不要用 GM 命令停止事件 56，也不要直接执行原生 `arena sendRewards`。

事件保护有效期到 2050 年，控制器自 2049 年起拒绝继续使用旧设置。没有定制核心源码，无法证明所有未知回调都被消除；不要手工改保护事件。

## 常见错误与处理

| 现象 / 提示 | 原因及处理 |
|---|---|
| 找不到 `mangosd.conf`、模块或 `mysql.exe` | 解压位置过深、只复制了部分文件、或 `Database\bin` 不完整。按安装树摆放，不要改模块名。 |
| 窗口闪退、中文乱码、PowerShell 解析错误 | 从完整下载包重新解压，保持 UTF-8 BOM。用 BAT 启动；不要只执行某个 PSM1。安全软件拦截时先确认被拦截文件。 |
| “请先关闭世界服务器 mangosd” | 仍有世界服进程，包括另一个测试服。关闭对应世界服，保留 MySQL。 |
| 无法写入、访问被拒绝、锁文件被占用 | 当前账户没有目录权限或另一个控制器正在运行。关闭另一窗口，使用可写的本地目录；不要把删除账本当修复方法。 |
| SQL 执行失败、Access denied、连接失败 | MySQL 未启动、配置连接不正确或数据库账户权限不足。检查本地配置，错误日志公开前隐藏密码和角色资料。 |
| “世界数据不符合 V4 升级要求”、事件描述/核心版本不符 | 缺少 V4 布局、数据已被其他工具改动，或使用了不同核心。此仓库不负责自动安装 V4，不要绕过校验。 |
| 13318 / 18086 被占用 | 另一个副本或软件占端口。确认进程用途后关闭该测试副本，不能误停正式 MySQL。 |
| 独立数据库初始化失败、世界副本未就绪、关服超时 | 检查空闲磁盘、TEMP 写权限、原 `DataDir`、DLL 和副本日志。主要日志为对应 `preview-*` 目录中的 `mysql-init.err`、`mysql.err`、`world.out`、`world.err`。失败的名单不能用于正式发奖。 |
| “预览已过期”或计算期间数据发生变化 | 预览后开过服、发生积分/队伍/邮件等数据变化。再次关服并选择 5，完成后直接进行 6。 |
| “只有正在进行的 S1、S2、S3 可以结算” | 准备期或已结算状态不能发奖。查看选项 7；已结算就按顺序开始下一季。 |
| “需要先结算 S1 / S2” | 禁止跳季。完成上季的 5、6 后再开始下一季。 |
| 获奖名单为空 | 没打比赛或未达到本端资格可能属于正常结果。几场比赛不保证领奖，也不能用空名单证明实物发奖正常。 |
| 无法判定唯一冠军 / 第一名并列 | 工具不会猜测季冠。保留名单和日志，核实原端排名规则后再处理，不要手改预览文件。 |
| “禁止撤销”“操作后数据已变化” | 已产生新数据或缺少完整提交后记录。保护正常生效，不能强行回档。 |
| “存在中断操作” / “事务已经提交” | 保持世界服关闭，选 9 恢复中断操作；不要反复选 6，不要删除 `pending.path` 或账本。 |
| 控制记录不属于此目录 / 本地备份丢失 | 服务器根目录被移动、库被替换，或 `.arena-settlement-v5` 丢失。恢复匹配的原路径和备份；本版不支持自动迁移。 |
| 事件 56 保护、S4 隔离、赛季时间被改变 | 可能混用了旧控制器或 GM 命令。保持关服，保留日志和备份，先查明改动。 |
| “已有结算奖励，禁止恢复” | 选项 10 不能恢复仍有 V5 正式奖励的环境，以免重新启用原生自动机制。 |
| 卖紫色荣誉散件 / 事件 56 活动 | 单凭装备颜色或事件 56 无法判断赛季。准备期使用现有基础荣誉商品池，不逐件重建历史补丁日期。 |

控制台日志在 `服务器根目录\.arena-settlement-v5\logs`。错误反馈应包含操作选项、完整错误文字和经过脱敏的日志；不要上传原始配置、SQL 副本、账户信息或整个备份目录。
